# Portfolio Checklist

Use this checklist before sharing FareScout with recruiters or potential employers.

## GitHub Profile

- Create a special repository named `Desdem0n`.
- Copy the content from `docs/GITHUB_PROFILE_README.md` into that repository's `README.md`.
- Pin `farescout` as the first featured repository.
- Add a concise GitHub bio focused on full-stack JavaScript and API-backed apps.
- Add repository topics to FareScout:
  - `nodejs`
  - `javascript`
  - `flight-search`
  - `api-integration`
  - `responsive-design`
  - `portfolio-project`
  - `saas-mvp`

## FareScout Repository

- Keep the README screenshot current.
- Keep `PRD.md` visible from the README.
- Keep the case study visible from the README.
- Confirm GitHub Actions check is passing.
- Confirm `.env` is ignored.
- Add a public demo URL after deployment.

## Public Demo

- Deploy the backend to Render, Railway, Fly.io, or Azure App Service.
- Add `IGNAV_API_KEY` as a private environment variable in the hosting dashboard.
- Add the live demo link near the top of `README.md`.
- Re-test WAW to LTN and WAW to LHR after deployment.

## Employer Review Flow

The ideal review path is:

1. GitHub profile README.
2. Pinned FareScout repository.
3. README screenshot and recruiter snapshot.
4. Case study.
5. PRD.
6. Running app or deployed demo.
